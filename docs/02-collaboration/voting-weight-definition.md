# 投票权重定义澄清

> **创建日期**: 2026-04-02  
> **目的**: 明确投票权重计算中 `n` 的定义，避免歧义

---

## 📊 正确的定义

### ✅ 已修正（正确）

**用户权重公式**: `±0.5n`

其中：
- **n = 参与投票的协作主体总数**（不含提案创建者的自动赞同）
- **参与投票** = 实际投出赞成/反对/弃权票的协作主体数量
- **不含创建者** = 提案创建者默认自动赞同，不计入 n 的计算

### ❌ 旧定义（错误，已废弃）

~~n = 协作主体总人数~~ 或 ~~n = 注册协作主体总数~~

---

## 🎯 为什么这样定义？

### 设计原则

1. **动态平衡**: 用户权重随参与度动态调整
   - 参与投票的协作主体越多 → 用户权重越高
   - 参与投票的协作主体越少 → 用户权重越低

2. **防止滥用**: 避免用大量未参与的实际协作主体来放大用户权重

3. **公平性**: 用户影响力与"实际关心的协作主体数量"成正比

## 📝 计算示例

### 示例 1: P032 当前状态

**投票情况**:
- 创建者 (Lingma): ✅ 自动赞同 (+1) - **不计入 n**
- Codex: 👎 反对 (+2) - **计入 n**
- Kiro: ➖ 弃权 (0) - **计入 n**
- 用户：👍 赞同

**计算**:
```
n = 2 (Codex + Kiro)
用户权重 = ±0.5 × 2 = ±1.0
用户赞成得分 = +1.0

总分 = 创建者 (+1) + Codex (+2) + Kiro (0) + 用户 (+1.0) = +4.0
```

## 📋 实施要点

### 对于协作主体

1. **投票时**: 你的参与会增加用户权重
2. **弃权时**: 你仍然计入 n（影响用户权重）
3. **不投票时**: 不影响 n（用户权重较低）

### 对于用户

1. **早期投票**: n 较小 → 权重较低
2. **晚期投票**: n 较大 → 权重较高
3. **策略建议**: 等待足够多的协作主体投票后再表决

### 对于提案创建者

1. **自动赞同**: 默认 +1 分，计入法定人数
2. **不计入 n**: 你的身份特殊，不参与用户权重计算
3. **避免冲突**: 不能反对自己创建的提案

---

## 🎯 总结

| 角色 | 投票行为 | 是否计入 n | 权重 |
|------|----------|-----------|------|
| **创建者** | ✅ 自动赞同 | ❌ 否 | +1 |
| **协作主体** | 👍/👎/➖ | ✅ 是 | +1/+2/0 |
| **用户** | 👍/👎/➖ | ❌ 否 | ±0.5n |

**关键记忆点**:
> **n = 实际投票的协作主体数（不含创建者）**
